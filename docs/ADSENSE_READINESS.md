## Project findings

- Google sign-in is required in the production matchmaking flow. The backend signs temporary chat tokens and stores account and compliance records using Drizzle/MySQL. Optional Google Sheets registration synchronization and server-stored image uploads also exist. Ordinary text is process-local; video/audio use WebRTC, with configurable STUN/TURN. Both peers' readiness starts offer/answer and ICE exchange. Video mode warms media during searching and connects automatically in the room after permission; a separate Join click is not always required.
- Single-process room/queue state limits horizontal scaling. Direct WebRTC may disclose network IPs. A TURN service and real network/device tests are operational requirements, not new services added here.
- Cloudflare static assets (`wrangler.toml` and `wrangler.jsonc`), Netlify static hosting, Render backend blueprint, Docker/Compose and VPS deployment documentation coexist. Client endpoint resolution defaults non-local frontend hosts to the existing Render backend. Setting only backend environment variables does not configure a separately built static frontend.
- The former `AdContainer.tsx` was unused: it fetched backend settings and emitted an uninitialized dummy ad slot. There was no functional AdSense script or ads.txt integration. The environment example contained only a publisher placeholder. No repository-written iframe wraps Meetly or the video UI; WebRTC uses video elements. Live homepage inspection showed Google Identity Services button iframes.

## IFRAME warning

The observed homepage renders as a top-level document and the sign-in buttons are embedded Google Identity Services frames. Those third-party areas cannot be treated as Meetly editorial ad inventory. The specific AdSense-account preview was not accessible, so the exact area behind the reported warning cannot be proven. Existing `X-Frame-Options: DENY` on Express/static hosts can also prevent framed previews. The warning alone does not establish a broken site or failed review. Framing protection was retained; ads are never injected when Meetly itself runs inside a frame. Do not add ads inside a login iframe or weaken security headers just to clear a preview notice. See Google's [preview documentation](https://support.google.com/adsense/answer/9262310?hl=en) and [iframe policy FAQ](https://support.google.com/adsense/answer/3394713?hl=en).

## Implementation

- A Vite build plugin validates the public publisher ID, adds `google-adsense-account` to the actual HTML head and emits plain-text `/ads.txt`. No ID means no account meta tag, no seller entry and no advertising; ads.txt contains only a configuration comment. Explicit activation with an invalid/missing ID fails the build.
- The head entry loads the standard async Google script, with `crossorigin="anonymous"`, only on known published article URLs. No script on `/`, discovery pages, the blog index, policy/safety pages, forms, unknown articles or errors. No manual slot IDs, duplicate pushes or legacy page-level configuration are used. Load failures are nonfatal and do not retry.
- A navigation boundary forces a fresh document when entering/leaving an eligible article, including history navigation, before chat components render. Removing a script alone would not unload its running JavaScript. This changes only those navigations when ad serving is enabled.
- Ads require `ENABLE_ADS=true`, a valid `ADSENSE_CLIENT_ID`, and `ADSENSE_CMP_READY=true`. The last flag confirms operator setup; it is not visitor consent and does not implement a CMP. Google's published consent message must handle actual choices and withdrawal. Defaults remain off.
- Static builds now run the existing SEO prerenderer, matching full builds. Added About/Contact content and links, sitemap entry, policy/advertising links from articles, and removed duplicate blog route declarations. Browser zoom is allowed. Narrow headers can wrap fixed-width GIS controls.
- Age/policy acceptance is unchecked initially, checked before matchmaking, and visible to returning signed-in users. Session-level acceptance can be restored for the same tab. This is self-attestation, not verified age. Removed fabricated online-count inflation in both server and client.
- Corrected conflicting sign-in/local-storage and video-start disclosures; disclosed uploaded-photo storage; removed unverified database-encryption/automatic retention promises; clarified that all sexual content is prohibited regardless of consent. Expanded safety and text-versus-video articles with concrete Meetly scenarios; removed several unsupported verified-adult/privacy claims in discovery and prerender content. Existing policy documents still require operator/legal review.

## Readiness: not ready to submit yet

1. **Account verification/approval and consent setup remain outstanding.** The supplied publisher ID is configured. Verify ownership, configure consent, obtain Google's review decision and inspect live delivery after an approved deployment. Technical integration does not prove eligibility.
2. **Private communications cannot carry AdSense ads.** Google's [ad placement policy](https://support.google.com/adsense/answer/1346295?hl=en#Ads_in_private_communications) excludes screens focused on private chat/video. This implementation restricts inventory to editorial articles. Google [reviews the entire site](https://support.google.com/adsense/answer/7584263?hl=en); editorial isolation does not bypass that review or make a random-chat site automatically acceptable.
3. **UGC moderation remains high risk.** Self-attested age and Google account sign-in do not establish adult identity. The on-device classifier uses skin-color heuristics, not reliable comprehensive moderation; peers can expose harmful material before a report or skip. Report/Block/Leave and text filtering exist, but there is no demonstrated continuous human moderation or comprehensive server-side video screening. Confirm staffed reporting, escalation, minor/CSAM handling and actual response coverage before review. Google makes publishers responsible for [all monetized content, including UGC](https://support.google.com/adsense/answer/10008391?hl=en); policy enforcement can apply at site level.
4. **Operator/legal details are incomplete.** Existing Terms and Grievance pages contain pending entity/address/officer details and hard-coded contacts on an older domain. Verify the actual operator identity, functioning mailboxes, appointment, jurisdiction, processing partners and cross-border hosting against the deployed service. No legal identity, incorporation status, officer or address was invented. `.env.example` no longer assumes a private limited company. Runtime legal configuration does not automatically rewrite those hard-coded pages.
5. **Privacy operations must match disclosures.** MySQL durability, encryption/backups, log residence/retention, report deletion, evidence preservation, image cleanup and Google Sheets handling need operational evidence. The repo has overlapping browser-to-Apps-Script and server-side Sheets paths; review the actual sheet access and deletion behavior. Legal/retention statements inherited from earlier work are not certified by this change. The local smoke tests use in-memory storage and do not establish production durability.
6. **Editorial review is still needed.** Seven published guides exist; some remain short, generic and repetitive. Article length alone is not an approval threshold. Review factual accuracy, distinct value, authorship, publication dates, similar generated sections and the scheduled daily AI publishing workflow. The workflow was inspected and left unchanged; no articles were externally published. Google's [inventory-value rules](https://support.google.com/publisherpolicies/answer/10502938?hl=en) prohibit low-value inventory. The hand-authored prerender summaries can drift from React pages and should be reviewed together.
7. **Consent is not established by this patch.** Publish and test a Google-certified CMP for applicable traffic, especially EEA/UK/Switzerland, with reject/manage and withdrawal choices as required. Also review applicable US state and other regional choices. Do not treat the 18+ or policy checkbox as ad consent. See [Google's CMP requirements](https://support.google.com/adsense/answer/13554116?hl=en).

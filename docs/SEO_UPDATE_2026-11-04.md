# Meetly search visibility update — 4 November 2026

The owner requested the 120 baseline counter back, plus better discovery for “Meetly”, “make friends online”, “friends online”, “talk to strangers” and related text/video chat searches. The frontend now starts at 120 and adds the existing measured active chat-session count. Backend operational statistics remain actual counts. This does not measure every anonymous visitor to the homepage; sign-in/active chat sessions drive the existing presence system.

## What the live check established

The live robots.txt and sitemap were publicly accessible, and the friends/stranger/video discovery routes already returned readable prerendered HTML with their own titles and canonicals. The newest AdSense ads.txt was also live. A deliberately nonexistent URL returned HTTP 200 with the homepage content and homepage canonical: this is a concrete soft-404 risk. The homepage request timed out on one attempt, so consistent uptime still needs monitoring. These observations do not prove the reason for Google's indexing decisions.

The available web searches did not surface meet-ly.in, but that is not an authoritative Google index or ranking report. The owner confirmed the domain is already verified in Search Console. No authenticated Search Console connector is available in this session, so coverage, manual actions, Google's selected canonical and crawl history could not be inspected or changed. No indexing request or sitemap submission was made on the owner's behalf.

## Changes

- Restored the requested frontend display of **120 + active sessions**, including HTTP stats refreshes and live WebSocket updates. The tooltip explains the baseline.
- Updated the homepage title to “Meetly | Make Friends Online & Talk to Strangers”, the friends page to “Make Friends Online Free | Meetly Text & Video Chat”, and the stranger-chat page to “Talk to Strangers Online | Free Chat on Meetly”. Descriptions explain the service, free access, adult eligibility and Google sign-in without promising safety or a guaranteed match. Existing URLs are preserved.
- Added substantive service-specific content, first-conversation examples, expectations and safety limits to the two main discovery pages. `content/discovery.json` supplies the same new sections to React and the prerenderer, rather than hidden keyword blocks. Added links to relevant guides and discovery pages. No typo-targeting doorway pages, fake reviews or artificial links were added.
- Added a WebSite alternate name to distinguish Meetly by Evolix Studio. Normalized client canonical URLs so home uses a trailing slash and page URLs have no query, fragment or trailing slash. Existing FAQ schema on the two discovery pages did not match the visible FAQs and was removed; matching blog FAQs remain eligible for schema markup, without any rich-result promise.
- Prerendered articles now include BlogPosting JSON-LD, real article dates and `og:type=article` before JavaScript executes. Metadata is HTML-escaped. The build sitemap derives URLs from pages actually generated, including all published articles, and excludes errors. Only edited discovery pages receive the current update date; published article dates come from their records.
- Generated an actual noindex `404.html`, switched Cloudflare assets to `404-page`, removed Netlify's catch-all HTTP-200 homepage rewrite, and made Express serve known prerendered pages or a real 404. Existing `/guidelines` and `/report-abuse` links retain permanent redirects. Backend API and chat routes remain handled before static pages.
- Added optional `GOOGLE_SITE_VERIFICATION` build support. This is unnecessary if the existing DNS verification is intact; no token was invented or verification method changed.

## Search Console steps for the already-verified property

1. In URL Inspection, inspect `https://meet-ly.in/`. Record whether it is indexed, the exact exclusion reason if any, last crawl, robots allowance, fetched status, user-declared canonical and Google-selected canonical. Use **Test live URL** after the deployment completes. View the rendered HTML/screenshot to confirm the new title and readable content.
2. Inspect `https://meet-ly.in/make-friends-online` and `https://meet-ly.in/chat-with-strangers` the same way. If the pages pass the live test, use **Request indexing** once per updated priority URL.
3. Submit/check `https://meet-ly.in/sitemap.xml` in Sitemaps. It must be fetched successfully as XML. Review Page indexing for “Crawled — currently not indexed”, “Discovered — currently not indexed”, duplicates, soft 404s or server errors; each needs its own diagnosis. Check Manual actions and Security issues as well.
4. In Performance, compare the “Meetly” branded query and non-brand queries separately. Track impressions, clicks, click-through rate, landing page and average position over time rather than expecting an immediate top result. Queries such as “make friends online” and “talk to strangers” are competitive; useful distinct content, genuine mentions/links and a consistently working service matter alongside technical fixes.
5. Confirm Cloudflare deploys the new commit and serves the new title, XML sitemap and real 404 status. Pushing source to GitHub is not proof of a successful frontend deployment. Hosting environment variables can override checked-in public build settings.

Google decides whether and when to index pages and how to rank them. A sitemap, keyword changes or an indexing request cannot guarantee inclusion or first position. Reference: [Google technical requirements](https://developers.google.com/search/docs/essentials/technical), [title guidance](https://developers.google.com/search/docs/appearance/title-link), [sitemaps](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview), [requesting recrawls](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl), [soft 404 diagnosis](https://developers.google.com/search/docs/crawling-indexing/troubleshoot-crawling-errors), [Cloudflare 404 routing](https://developers.cloudflare.com/workers/static-assets/routing/static-site-generation/), [Netlify 404 handling](https://docs.netlify.com/manage/routing/redirects/redirect-options/).
